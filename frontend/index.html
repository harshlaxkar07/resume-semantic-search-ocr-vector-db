How semantic search works here

Two stores work together: ChromaDB holds the vectors for similarity search, and MySQL holds the file metadata and extracted text that gets shown alongside each result.

Ingestion path

  1. Read — the PDF text layer is pulled out page by page.
  2. OCR fallback — pages with no text layer are rendered and recognised, so scans work too.
  3. Clean — whitespace and layout artefacts are normalised.
  4. Embed — the cleaned text becomes a dense vector.
  5. Store — the vector goes to ChromaDB, the metadata and text to MySQL.

Query path

  1. Embed the query — your sentence is embedded with the same model.
  2. Compare — ChromaDB ranks every stored résumé by similarity.
  3. Join — the top matches are enriched with their MySQL records.
  4. Return — filenames, paths and similarity scores come back in rank order.
